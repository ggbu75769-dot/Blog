# Codex R1 적용 및 반복 검증 지시문

HOMEFEED BLOG OS 4.1.0-r1을 현재 저장소에 실제 구현하라. 이 패키지는 기존 최종본의 교체본이다. 공개 게시·네이버/티스토리/자체 블로그 로그인·게시 API·매크로는 만들지 않는다. 사용자 목표는 주제 발굴부터 기획·조사·그 블로그다운 원고 작성·최종 검수·실제 자산·복사할 수 있는 출력까지의 자동화다.

## 시작
현재 branch·git status·untracked·기존 AGENTS와 프로젝트를 확인하고 사용자 변경을 보존한다. 패키지 AGENTS로 기존 지시를 덮어쓰지 않는다. 기존 스택을 이유 없이 다시 만들지 않는다.

README, docs/00, docs/25, docs/26, docs/27, docs/28, docs/29, docs/16을 읽고 계약과 현재 구현의 차이를 기록한다. 먼저 `python tools/validate_bundle.py`, `python tools/run_r1_checks.py`를 실행한다. 파일이 변경되기 전 전달본은 `python tools/verify_checksums.py`로 확인할 수 있다.

## 작업 선택
`contracts/task_order.txt`의 의존순서를 지킨다. T051~T060이 추가되어 숫자순 실행과 다르다. 기존에 구현한 기능은 재구현하지 말고 검증·차이 수정부터 한다. 키·계정·예산이 없어도 REPLAY를 먼저 구현하며 가능한 개발을 계속한다.

## 모든 변경의 반복 순서
1. 요구사항·실패 사례·현재 코드로 문제를 재현한다. 재현하지 않은 추정은 구분한다.
2. 수정 전 실패하고 수정 후 통과할 가장 작은 시험을 추가한다.
3. 필요한 최소 범위를 구현한다. 문서만 다시 쓰고 끝내지 않는다.
4. 신규 시험과 영향을 받는 기존 시험을 실행한다. 기존 정상 원고도 계속 통과해야 한다.
5. schema/API/SQL/prompt/상태/문서/작업 추적성을 함께 고친다.
6. 실제 작업이 필요한 DB·HTTP·LLM·사람·에디터 시험은 해당 환경에서만 판정한다.
7. 남은 결함과 새로운 반례를 점검하고 가능한 범위에서 같은 루프를 반복한다.

## 반드시 막을 것
미갱신 통계의 숫자0 변환, 다른 블로그 경험 혼입, Python/JavaScript 해시 불일치, 구버전 검수 재사용, 자료 권리철회·만료 무시, metadata를 본문완독으로 처리, REPLAY를 LIVE로 승격, 파일누락·상위경로·symlink·외부명령 유입을 막는다. writer가 승인·예산·서버 identity를 생성하지 못하게 한다.

## 원고 성능의 별도 기준
안전한 원고가 곧 매력적인 원고는 아니다. 같은 자료·비용에서 기획 후보를 비교하고 새 답·첫 화면·개성·완결성을 평가한다. 사용자에게 실제로 고칠 것이 줄었는지는 독립적인 사람 평가와 수정시간으로 확인한다. 경험을 지어내거나 고의 오타·탐지 회피로 자연스러움을 흉내내지 않는다. 확률을 교정하지 않았으면 바이럴 성공확률을 출력하지 않는다.

## 종료·보고
선택한 작업의 실제 완료 조건이 통과하면 결과를 보고한다. 고정된 실패를 숨기기 위해 테스트를 지우거나 약하게 만들지 않는다. 무한 반복·무한 유료 호출·계정 제한 우회·운영배포는 하지 않는다. 외부 입력이 필요한 부분만 구체적인 blocker로 남기고 가능한 나머지를 끝낸다.
