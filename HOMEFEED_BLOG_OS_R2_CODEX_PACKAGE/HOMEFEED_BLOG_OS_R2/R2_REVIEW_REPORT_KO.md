# R2 내용·집필 품질 감사와 수정 보고서

기준일 2026-09-16. 확인 대상은 실제로 제공된 R1 패키지다. 프로젝트 소스 저장소·실제 계정·실제 공개 성과를 감사한 것은 아니다.

## 이번 개정의 중심
원고의 내용과 독자에게 남는 답이 우선이다. R1에서 이미 사실·권리·자연스러움 규칙을 요구했으므로 이를 처음 발견한 원리처럼 설명하지 않는다. 이번에는 그 규칙과 실제 예제의 간격을 줄이고, 최종 원고에서 정확히 어느 문장이 가치를 주는지 연결했다.

## 실제 확인과 조치
| 항목 | 확인 자료 | 수행한 조치 | 남은 검증 |
|---|---|---|---|
| 설명 반복과 추상성 | examples/export/article.txt | 동일한 Datalab 예제를 실제 판단 문제와 가상 계산 표로 다시 씀 | 독립 독자 선호 비교 |
| 내부 출처 코드 | reference_core/render.py, examples/r1 렌더 | 읽을 수 있는 작은 각주와 기관명/원문 목록의 새 renderer | 실제 네이버/티스토리 입력 |
| 보안 시험 원고의 경로 | R1 rendered_reference의 악성 문자열 | tests/adversarial로 이동; 원래 보안 검사는 유지 | 제품 공개 큐와 테스트 파일의 배포 분리 |
| 최종 내용 가치의 연결 | R1 문체·기획·평가 명세 | payoff 앵커·본문 해시·검토 서비스 권한의 sidecar와 참조 검사 | 실제 의미 검수자·모델 연동 |
| 표현/내용 수정의 혼동 | 비평·문체 프롬프트 | 자료 부족→조사, 질문 문제→재기획, 문장 문제→부분 편집 | 실제 집필 실행 비교 |
| 실전 원고 예제 범위 | R1 기술적 예제 1편 | 수정본 1편+새 설명형 원고 2편, 출처·한계 포함 | OTT/실제 체험/다른 장르 확대 |

보안 시험 데이터는 원래 R1에서도 부정 예제로 표시되어 있었다. 이번 수정은 이를 발견되지 않은 XSS 보안 사고라고 주장하는 것이 아니라, 독자용 결과와 같은 예제 경로에 둔 혼동을 줄이는 것이다.

## 반복 검증 기록
기준선에서 문서 검사 73건과 R1 회귀검사 112건을 다시 통과했다. 새 샘플 첫 렌더에서는 required `checked_on` 필드 누락을 발견하여 출처 확인일을 샘플에 채웠다. 스키마 조건을 완화하지 않았다.

처음 새 오프라인 검사 44건을 통과한 뒤, 출처 표기를 더 간결하게 바꾸고 중복 출처의 번호 연결·참고 주석의 프로덕션 승격 방지·검토자 역할·중요 예외 보존 4건을 추가했다. 최종 새 회귀검사는 **48 PASS / 0 FAIL**다.

문서를 31개에서 39개로 늘리면서 기존 검사기의 ‘정확히 00~30’ 파일 목록 조건이 한 번 실패했다. 필요한 파일을 삭제하거나 검사를 없애지 않고 ‘정확히 00~38’로 개정했다. 최종 기존 문서 검사 **73 PASS / 0 FAIL**, 기존 R1 회귀검사 **112 PASS / 0 FAIL**다.

## Codex가 이어갈 우선순위
1. 이 세션의 원고를 좋은 형식의 예시로 읽되 모든 글을 같은 문장 구조로 복제하지 않는다.
2. 실제 앱에서 주제→기획→근거→집필→최종 내용 검수→독자 출력 한 경로를 연결한다.
3. 실제 독자의 블라인드 평가와 수정 시간을 기록하여 부족한 형식을 개선한다.
4. 수동 게시 후에만 실제 홈피드·조회수와 연결한다. 품질과 노출 기회를 별도 학습한다.

전체 명세: docs/31~38. 실제 명령 로그: reports/r2. 기존 실행 보고서: reports. 모든 제품 인수시험은 R1 140개+R2 30개 모두 NOT_RUN이다.
