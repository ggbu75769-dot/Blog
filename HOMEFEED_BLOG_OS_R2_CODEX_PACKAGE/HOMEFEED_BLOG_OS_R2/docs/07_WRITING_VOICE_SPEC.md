# 07. 실제 집필·문체·교정 작업명세

문서 기준: 2026-09-15 · 설계 동결: 4.1.0-r1 · 공개 게시: 사용자 수행


## 집필 품질의 목표
가짜 체험이나 판별기 우회가 아니라 구체적이고 읽히는 원고를 만든다. 사람의 글도 형식적일 수 있으므로 ‘AI스러움’이라는 한 점수로 판정하지 않는다. 질문 해결·자연스러움·블로그 관점·검증 가능성을 나눠 평가한다.

## 문체 프로필
profile에는 register, rhythm_notes, paragraph_preferences, opening_preferences, closing_preferences, allowed_emphasis, avoided_patterns, editorial_lens, example_spans, counterexamples가 들어간다. 예문은 사용자 소유·사용허가 자료만 입력한다. 경쟁자 원문은 구조 분석에만 쓰고 표현을 따라 쓰는 학습 표본으로 사용하지 않는다.

초기 샘플8~15편은 출발점으로 제안한다. 없으면3개 짧은 샘플로 방향을 정한다. 글마다 다시 말투를 물어보지 않는다. 프로필 변경은 version을 새로 만들고 이전 원고의 작성 맥락을 보존한다.

## 단계별 집필
W1 논리 골격: 새 답과 각 섹션에서 독자에게 줄 정보를 정한다.
W2 사실 초안: EvidencePack만으로 주장·숫자·조건을 작성한다. 새로운 사실이 필요하면 조사요청을 반환한다.
W3 반대 검토: 단정, 상관관계의 인과 해석, 예외 생략, 비교 대상 혼동, 타인 경험의 전용을 찾는다.
W4 문체 편집: 내용은 유지하면서 구체적인 표현과 해당 블로그 리듬으로 고친다.
W5 의미 보존: 초안과 편집본의 주장·날짜·대상·인용·확신 수준을 대조한다.
W6 제목·첫 화면 편집: 최종 본문의 실제 답에 맞게 약속을 정리한다.
W7 한국어 교정: 조사·띄어쓰기·중복·지시어·문단 전환을 확인한다.
W8 서버 출고검사: 스키마·해시·근거·권리·파일·미완성 표식을 검사한다.

## 실용적인 문체 지시
독자에게 이미 알려진 배경을 길게 반복하지 않는다. 중요한 대상을 ‘이것’, ‘해당 부분’처럼 모호하게 부르지 않는다. 조건을 먼저 알면 이해가 쉬운 글은 조건부터 쓴다. 감탄사를 억지로 넣지 않는다. 자연스럽게 짧은 문장과 긴 문장이 섞이되 랜덤 길이를 목표로 삼지 않는다. 불필요한 ‘오늘은/이번 포스팅에서는/지금까지’를 매번 붙이지 않는다. 개인의 판단은 승인된 관점과 근거가 있는 범위에서만 쓴다.

## 표현 편집 예시
수정 전: ‘다양한 기능을 통해 사용자 경험을 혁신적으로 향상시키는 완벽한 서비스입니다.’
수정 후: ‘새 기능을 쓰기 전에 적용 대상을 먼저 확인해야 합니다. 같은 서비스라도 계정과 버전에 따라 보이는 메뉴가 다를 수 있으니까요.’
이는 문체 예시다. 실제 원고에서는 계정·버전 차이가 있다는 근거를 확인해야 하며 해당 사실이 없으면 이 문장을 쓰지 않는다.

수정 전: ‘수납함은 삶의 질을 높이는 필수 아이템입니다.’
수정 후: ‘무엇을 넣을지보다 무엇을 자주 꺼낼지 먼저 정해보세요.’
두 번째 문장은 제안이지 작성자의 실제 체험이나 상품 효과를 주장하지 않는다.

## 내용 보존 필수 검사
일부→전체, 순차 적용→즉시 적용, 가능→확정, 특정 조건→무조건, 타인 후기→내 후기 변환을 차단한다. 정규식은 검사 후보를 찾는 보조 장치다. 최종 본문에서 실제 주장을 별도 추출해 claim graph와 대조하고 숫자·단위·날짜는 코드도 검사한다. 재작성 모델이 새로운 claim ID를 생성했더라도 원문에 근거가 없으면 통과하지 않는다.

## 최근 글 반복 검사
같은 블로그 최근30편의 도입·소제목·결론을 비교한다. 문장 복제, 같은 비유, 같은 광고 문구의 반복을 경고한다. 필수 서비스명·전문용어·출처명 반복은 무조건 금지하지 않는다. 다양화는 사실과 논지를 유지하는 범위에서만 한다. 반복 감소를 위해 랜덤 사건·개인 경험을 넣지 않는다.

## 수정 범위와 종료
문체 자동수정 최대2회, 사실 보강 최대2회를 기본 정책으로 둔다. 동일 결함이 반복되면 NEEDS_REVIEW로 이동한다. 전체 재생성보다 해당 블록만 수정하며 관련 claim·제목·출력물의 해시를 재계산한다. 모든 수정은 parent_revision_id를 가진 새 버전이다. 사용자 편집은 즉시 저장되지만 기존 검수 통과를 상속하지 않는다.

## 자연스러움 평가 프로토콜
30편을 채널2개 이상·형식3개 이상으로 구성한다. 같은 평가를 만드는 모델과 별개의 인간2명이 출처 보지 않고 문장 자연스러움·관점 일관성·답의 충족·과장 정도를 평가한다. 사실/권리 검토는 별도 근거 화면으로 한다. 하나라도 중대 사실 오류나 가짜 체험이 있으면 릴리스 실패다. 점수·수정시간 목표는 PRD에 있으며 미실행 결과를 기입하지 않는다.


## R1: 원고 개선을 측정하는 방식
첫 화면 기대 충족, 구체적인 새 답, 논리 전환, 블로그 관점, 불필요한 반복, 최종 게시까지 사람의 수정시간을 별도로 평가한다. AI 판별기 통과율은 목표에 포함하지 않는다. fact/quote/proposal/hypothesis를 유지하고, 근거가 필요한 문장을 모두 무미건조한 일반론으로 바꿔 검수를 피하지 못하게 한다. 똑같은 안전한 서론과 결론만 재사용해도 독창성 실패가 될 수 있다. 평가 카드와 선택된/거절된 기획의 샘플링은 docs/27에서 고정한다.


## R2 보완 우선 적용
내용·문체·독자 평가·독자용 출력의 상세는 docs/31~38을 함께 적용한다. 특히 부족한 내용은 문체로 덮지 않고 조사/재기획하며, 최종 본문의 실제 payoff 구절과 review 버전을 연결한다. R1 사실·권리·scope·최신성 gate는 약화하지 않는다. R2 예제는 인간평가·실제 에디터·트렌드 효과가 확인되지 않은 편집 기준용 원고다.
