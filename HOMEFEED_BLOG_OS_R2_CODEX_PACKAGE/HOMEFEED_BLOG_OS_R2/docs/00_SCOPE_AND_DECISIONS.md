# 00. 최종 범위와 결정 기록

문서 기준: 2026-09-15 · 설계 동결: 4.1.0-r1 · 공개 게시: 사용자 수행


## 1. 최종 요구를 한 문장으로
처음 한 번 블로그별 운영 방향·허용 자료·예산을 정하면, 서비스가 주제 발견→관심과 경쟁 조사→독창적인 내용 기획→근거 확보→블로그별 집필→교정→이미지 준비→출고 검사를 수행해 사람이 네이버·티스토리·자체 블로그에 옮길 수 있는 완성 원고를 만든다. **공개 게시, 계정 로그인, 예약 발행은 구현하지 않는다.** 사용자가 글을 올리는 데 동의했다는 이유로 주제 조사나 원고 완성까지 수동으로 돌리지 않는다.

## 3. 명시적 비범위
쇼츠·영상 제작·YouTube Shopping·Shopify·자동 댓글·공감·서로이웃·가짜 트래픽·계정 생성·CAPTCHA 회피·비공개 API·네이버 입력 매크로·링크 우회·AI 탐지 회피·현재 없는 통계 추정은 제외한다. 자체 블로그도 이번 버전에서는 출력만 제공한다. 게시 API를 “나중을 위한 옵션”으로 구현하지 않는다. 필요 시 다음 버전의 별도 승인된 변경요청으로 다룬다.

## 4. 목표와 보장의 구분
월100만은 제품의 성장 목표이지 기능 인수시험이 아니다. ‘좋은 글’은 독자 질문에 새로운 답을 주고 근거·문체·권리를 갖춘 원고라는 제품 기준이다. ‘홈판에서 선택될 가능성’은 실험할 가설이며 게시 전 확정할 수 없다. 관측·자료 부족을 AI 숫자로 보충하지 않는다. 공식 홈피드 안내는 개인화를 설명한다.[S01]

## 5. 미확정 운영 입력의 처리
실제 블로그 URL·기존 원고·CMS·API 키·월 예산·이미지 사용권은 제공되지 않았다. 이를 지어내지 않는다. 개발은 fixtures의 REPLAY 모드로 진행하고, 첫 실행 설정 화면에서 한 번 입력받는다. 미연결 공급자는 NOT_CONFIGURED이며 성공처럼 표시하지 않는다. 블로그가 1개뿐이면 1개에서 동작하고, 두 번째 프로필은 테스트 픽스처로만 검증한다.

## 6. 문서 우선순위
최신 사용자 확정사항→본 문서→requirements.json→도메인 스키마·상태·OpenAPI→각 상세 명세→예제 순이다. 같은 계층에서 충돌하면 구현자가 임의로 해석하지 말고 DECISION_LOG에 해결안을 남긴 뒤 계약과 시험을 함께 수정한다. 이전 V1~V3 문서를 이번 패키지 위에 겹쳐 적용하지 않는다.


## R1 동결 결정
4.1.0-r1이 final.1을 대체한다. 기존 17개 계약·검증 공백은 docs/25에서 추적한다. 정상적인 참고 예제도 계속 통과해야 하며 실패 조건만 늘려 생산을 마비시키지 않는다. 공개 게시는 여전히 사용자 수행이다. reference_core는 결정적 규칙의 참조 구현이며 실제 앱·LIVE 집필 모델·사람 검수의 대체물이 아니다.


## R2 보완 우선 적용
내용·문체·독자 평가·독자용 출력의 상세는 docs/31~38을 함께 적용한다. 특히 부족한 내용은 문체로 덮지 않고 조사/재기획하며, 최종 본문의 실제 payoff 구절과 review 버전을 연결한다. R1 사실·권리·scope·최신성 gate는 약화하지 않는다. R2 예제는 인간평가·실제 에디터·트렌드 효과가 확인되지 않은 편집 기준용 원고다.
