# 26. 기획 성공률을 높이는 편집 의사결정 — R1

## 목적과 범위
자동화의 생산물은 많은 초안이 아니라, 지금 독자가 읽을 이유가 있고 실제로 옮겨 쓸 수 있는 완성 원고다. 출고 안전조건과 기획 경쟁력을 별도 경로로 평가한다. 안전하다는 이유만으로 무미건조하고 기존 글과 같은 원고를 출고하지 않는다. 월100만은 주력 네이버 블로그의 성과 목표이며 예측된 결과가 아니다.

## 기회 탐색 → 기획 경쟁 → 집필의 세 단계
탐색 단계는 비교 가능한 수요 관측·공식 일정·주제 적합성을 본다. 수요가 미확인이면 조사 큐에 두고, 일정만 확인됐으면 자료준비만 한다. 표본의 개인화·관측 편향을 보존한다. 네이버 홈피드는 이용자의 관심에 따라 달라지므로 관측 순서를 전국 순위처럼 해석하지 않는다.[S01]

기획 경쟁은 같은 사건의 후보3개를 비교한다. 고정 필드는 reader_question, known_answer, new_answer, evidence_route, card_promise, visual_role, why_this_blog, why_now, counterargument, expiry_condition이다. 숫자점수는 정렬 보조이며 최종 결정에는 선택 근거와 반대 근거를 함께 저장한다. 검색 결과의 제목을 바꾸는 것만으로 new_answer를 채우지 못한다.

집필 단계는 선택된 기획의 질문과 근거를 그대로 전달한다. 해당 기획이 좋다고 평가한 모델이 최종 글의 자체 점수를 유일한 출고 판단으로 삼지 않는다. 다른 검수 단계는 실제 원문과 최종 글을 읽는다.

## 편집 우위 카드
| 항목 | 좋은 증거 | 부족한 답 |
|---|---|---|
| 지금 읽을 이유 | 공개된 변화·새 질문·실제 관심 관측 | 요즘 인기인 것 같음 |
| 새 기여 | 조건별 비교·원문 대조·설명되지 않은 질문 | 상위글을 자연스럽게 다시 씀 |
| 첫 화면 | 제목의 질문과 이번 글의 답 방향 | 날씨 인사와 개요 반복 |
| 시각 자료 | 차이와 대상을 보여주는 실제 사용 가능한 자산 | 사진 장수 채우기 |
| 블로그 관점 | 독자가 무엇부터 판단할지 일관된 기준 | 말투만 다름 |
| 제작 준비 | 근거·자산·만료·소요·게시기회 확인 | 일단 만들고 부족한 것은 나중에 |

## 예시: 정보가 없는 차별화 금지
설명용 사건 '서비스A가 새 기능을 공개함'에서 다음3개를 비교한다.
A: 새로운 기능10가지 — 공식자료에10가지가 없으면 탈락.
B: 기존 이용자에게 달라진 조건 — 적용 대상/버전/시점이 확인되면 후보.
C: 직접 써보니 달라진 점 — 실제 경험 기록이 없으면 공개 자료형으로 재기획하거나 보류.
이는 실제 급상승 소재를 검증한 예시가 아니다.

## 대기열을 고려한 선정
작성 시점이 아니라 사용자가 게시할 수 있는 시점까지 질문과 근거가 유효한지 검사한다. available_windows를 모르거나 원고 유효시간보다 늦으면 빠른 이슈를 무조건 생산하지 않는다. 시스템은 사용자 입력을 강제해 모든 연구를 멈추는 대신 오래 지속되는 질문으로 reframe하거나 자료준비를 진행한다. 완성 대기열 상한을 늘리는 것과 실제 게시 용량이 늘어나는 것은 다르다.

## 가치 있는 원고가 없을 때
최신 사건이 없거나 근거가 부족하면 사실을 지어내지 않는다. 같은 채널의 미해결 질문을 조사하되 그것을 현재 바이럴 후보로 허위표시하지 않는다. '신규작성0·조사3·선점준비2'도 올바른 실행 결과다. 원고 수를 채우기 위해 문체만 다른 중복글을 보내지 않는다.

## 학습 데이터
선정·탈락·보류·미게시 후보를 모두 저장한다. 미게시의 PV를0으로 넣지 않는다. 무작위 노출 실험이 아니므로 한 제목 때문에 성공했다고 단정하지 않는다. 사건·날짜·블로그를 묶어 데이터 분리하고, 기획 당시 알 수 없던 미래 통계를 정렬 입력에 넣지 않는다. 대박 한 편이 아니라 반복되는 유입과 작성비·수정시간을 함께 확인한다.
