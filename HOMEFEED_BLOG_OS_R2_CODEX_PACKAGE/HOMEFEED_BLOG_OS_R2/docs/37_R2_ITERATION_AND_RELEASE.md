# 37. 반복 개선·중단·출시 기준

## ‘완벽해질 때까지’의 실행 가능한 뜻
종료 조건 없는 재생성은 비용을 쓰고 원고를 평범하게 만들 수 있다. 이 서비스는 결함과 개선 가설을 먼저 적고, 해당 결함을 잡을 시험 또는 독자 평가를 만든 뒤 수정한다. 수정 전 기준선을 보존하고 결과를 비교한다. 같은 원고를 이유 없이 반복 생성하지 않는다.

```
실제 글 읽기 → 구체적인 부족함 표시 → 원인 분류
→ 필요하면 추가 조사 → 부분 수정 또는 기획 변경
→ 최종 사실·권리 검수 → 독자 관점 재평가
→ 개선 확인 / 보류 / 기존 버전 복귀
```

## 이번 수행 순서
1. 실제 R1 ZIP을 풀고 예제 원고, 집필 프롬프트, 평가 설계, 렌더 코드를 읽었다.
2. 기존 문서 검사 73건과 회귀검사 112건을 재실행해 기준선 통과를 확인했다.
3. 실제 원고의 편집 공백과 공개 출력의 코드 표시·시험 예제 경로를 확인했다.
4. 네이버 공식 품질 안내와 샘플의 실제 자료를 웹으로 재확인했다.
5. R1 원고 수정본과 다른 두 설명형 원고를 직접 작성했다.
6. reader renderer와 exact-anchor review 참조 코드를 구현하고 새 반례 검사를 추가했다.
7. DOCX·HTML 표시와 패키지를 확인한다. 각 실제 결과는 reports/r2에 기록한다.

샘플 첫 렌더에서 기존 PublicCitation 스키마의 `checked_on` 누락을 발견했다. 스키마를 약하게 만들지 않고 샘플 생성기에 확인일을 채운 뒤 다시 실행했다. 이는 샘플 제작 중 발견한 구현 오류이며 제품 운영 장애가 아니다.

## 배포 금지와 승인 구분
프로덕션 앱·DB·모델 연동을 실행하지 않았으면 실제 서비스 완료로 표시하지 않는다. 사람 평가를 수행하지 않은 상태는 UNKNOWN/NOT_RUN이다. 로컬 파일 표시 확인은 플랫폼 호환성 확인이 아니다. 트렌드나 공개 성과가 없는 샘플에는 바이럴 확률·승률을 붙이지 않는다.

## 초기 운영 확장 제안
주제·형식별로 검증된 영역부터 자동 원고 준비를 확대한다. 사실 정정이나 문체 퇴행이 발견되면 해당 형식만 보류하고 다른 검증된 작업을 계속할 수 있다. 최근 몇 편이 낮은 조회수였다는 이유로 본문을 곧바로 실패 학습하지 않는다. 노출 기회·통계 지연·주제 차이를 분리한다.

## 사용자가 받을 것
최종 원고와 원문 링크를 먼저 보여준다. 점수·분석·의심 부분은 별도 펼침 화면으로 둔다. ‘90점 원고’보다 실제로 어떤 답이 새롭고 어떤 조건이 남았는지 표시한다. 저가치 원고는 예쁘게 포장해서 큐를 채우지 않는다.
