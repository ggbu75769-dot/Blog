# 33. 집필·문체·부분 수정 명세

## 집필을 시작하는 조건
R1의 브리프·근거·권한이 준비되어야 한다. R2는 추가로 읽은 뒤 독자에게 무엇이 남는지와 그 답을 만들 재료가 있는지 확인한다. 근거 자료가 빈약하면 문장을 늘리지 않고 조사 요청을 반환한다.

## 실행 순서
| 단계 | 수행 내용 | 실패 시 |
|---|---|---|
| 질문 편집 | 중심 질문과 독자 상황을 한 문장으로 고정 | REFRAME |
| 재료 편집 | 사실·조건·비교·예·예외 중 필요한 재료 선택 | RESEARCH |
| 구성 편집 | 장르에 맞는 독자의 이해 흐름 설계 | REFRAME |
| 본문 집필 | 근거로 답을 실제 구현 | RESEARCH 또는 REWRITE |
| 내용 비평 | 기대 충족·논리·정보 이득·범위 확인 | 원인별 수리 |
| 문체 편집 | 불필요한 추상어·반복·어색한 전환 부분 수정 | LOCAL_EDIT |
| 사실 재검수 | 숫자·주체·조건·확신·경험 변경 재확인 | FACT_REVIEW |
| 카드 확정 | 실제 최종 답과 제목·대표이미지·도입 일치 | CARD_REPAIR |
| 독자 출력 | 출처와 최종 문장 보존, 내부 메모 제거 | REPAIR_EXPORT |

## 장르마다 첫 화면의 역할이 다르다
- 절차·문제 해결: 적용 대상과 첫 행동 또는 가장 중요한 구분을 일찍 알려준다.
- 비교·결정: 무엇을 기준으로 결론이 달라지는지 먼저 제시한다.
- 작품 해석: 스포일러 범위를 먼저 밝히고, 확인한 장면과 해석의 구분을 유지한다. 이야기를 전혀 보지 않고 장면을 상상하지 않는다.
- 실제 체험: 제공된 기록의 관찰로 시작할 수 있으나 기록이 없으면 안내·비교형으로 전환한다.
- 장면 중심 글: 흥미를 위한 짧은 전개는 가능하다. 필수 답을 일부러 끝까지 감추거나 외부 사이트로 보내지는 않는다.

모든 글에 ‘결론부터 말하면’을 붙이지 않는다. 첫 화면이 뒤의 내용과 어긋나지 않게 한다.

## 문체의 핵심
문체는 조사와 존댓말만이 아니라 무엇을 중요하게 비교하고 어디서 결론을 멈추는가다. 블로그별 관점은 승인된 범위로 사용한다. 없는 직업·사용경험·독자 반응을 설정하지 않는다.

감탄사, 반말, 오타, ‘솔직히’, ‘제가 직접’ 추가가 자연스러움의 기본 도구가 되어서는 안 된다. 문장 길이를 난수로 섞거나 같은 어미를 금지하는 방식도 사용하지 않는다. 정확한 용어와 핵심 조건의 반복은 허용한다.

## 잘라낼 것과 남길 것
| 대상 | 기본 행동 |
|---|---|
| 글의 제목을 다시 말하는 서론 | 새 정보가 없으면 줄임 |
| 독자에게 이미 알려진 장황한 배경 | 중심 질문에 필요한 만큼만 유지 |
| 장점·단점 개수를 채우는 항목 | 해당 자료에 없으면 삭제 |
| 안전조건·핵심 예외 | 가독성 때문에 제거하지 않음 |
| 이전 문단과 같은 결론 | 합치되 연결과 강조 기능 확인 |
| 진짜로 비교에 필요한 숫자 | 단위·조건·근거와 함께 유지 |
| 개인의 판단 | 판단임을 드러내고 사실과 구분 |
| 출처 코드 | 독자에게 읽히는 기관명·원문 링크로 바꿈 |

## 과도한 다듬기의 중단
이미 명확한 문장까지 모두 비슷한 말투로 고치지 않는다. 고칠 이유가 있는 block만 대상으로 한다. 변경 전후와 제거·추가된 정보 목록을 보존한다. 개선 가설이 없으면 재생성하지 않는다.

한 원고에 대해 내용 재구성 1회와 부분 편집 2회를 초기 상한으로 제안한다. 추가 조사가 필요한 경우는 별도 작업으로 돌린다. R1 전역 수리·예산 한도를 넘길 수 없다. 이는 비용 통제를 위한 설정이며 네이버 노출 규칙이 아니다.

## 수정 우선순위
사실 오류 → 핵심 질문 불일치 → 답과 재료 부족 → 구조 → 반복 → 개별 표현. 순서를 반대로 하면 잘못된 내용을 매끄럽게 다듬게 된다.

## 최종본 보존
카드나 본문을 고치면 R1 content hash와 R2 편집 review hash를 모두 갱신한다. 옛 검수는 새 문장에 자동 적용하지 않는다. 사용자가 실제로 붙여넣기한 원고를 후속 학습할 때에도 마지막 자동본과 사용자 수정본을 별도로 저장한다.
