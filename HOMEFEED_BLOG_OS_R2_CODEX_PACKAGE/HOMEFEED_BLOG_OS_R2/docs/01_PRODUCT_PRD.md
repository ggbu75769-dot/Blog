# 01. 제품기획서 · PRD

문서 기준: 2026-09-15 · 설계 동결: 4.1.0-r1 · 공개 게시: 사용자 수행


## 제품 약속
사용자는 매일 글감을 선택하거나 AI 초안을 다시 집필하는 사람이 아니다. 완성 원고를 읽고 선택해 올리는 편집 책임자다. 서비스는 오늘 발행할 이유가 있는 원고를 준비하되, 근거 없는 주제를 생산량 때문에 채우지 않는다.

## 주요 사용자 흐름
### 처음 한 번
실제 블로그 등록→핵심 분야와 인접 분야 승인→기존 글 또는 문체 샘플 선택→공개 가능한 사실·경험 지정→허용 소스·API 키 등록→예산 입력→생산 상한·평소 게시 가능 시간대 설정→샘플 한 편 확인→자동 제작 활성화. 게시 가능 시간대는 완성 원고를 준비할 목표창이며 외부 발행 스케줄이 아니다.
### 매일
오늘 화면에서 완성 원고·예외·오래된 대기 원고를 본다. 원고에서는 최종 제목·본문·이미지·출처가 보이고 내부 점수는 접힌다. 복사와 파일 저장 후 사용자 본인이 에디터에서 게시한다. 게시 URL과 시간을 선택적으로 기록한다. 실제 통계는 보고서 파일로 가져온다.

## 산출물 정의
원고 한 편은 제목, 본문, 소제목, 필요 시 표, 사용 가능한 실제 이미지, 캡션, 공개 출처, 카테고리·태그 제안, 블록별 전송 안내, 비공개 검수 기록을 가진다. 이미지 프롬프트와 ‘여기에 사진’ 표식만 있는 원고는 완성 원고가 아니다. 기획상 이미지 없이 완결되는 글만 text_only_allowed=true로 승인할 수 있다. 홈판형 대표이미지를 필요로 하는 기획의 자산을 조용히 생략하지 않는다.

## 성공 지표와 초기 인수 목표
| 구분 | 지표 | 초기 목표의 성격 |
|---|---|---|
| 성장 | 주력 블로그 달력 월 PV 1,000,000 | 방향 목표. 시점·달성을 보장하지 않는다. |
| 완성도 | 외부 링크 없는 본문, 자산 누락, TODO, 내부 메모 누출 등 중대 결함 | 출고 표본에서 0건이어야 한다. |
| 사실 | 중요 주장 오류·가짜 경험·허위 숫자 | 블라인드 평가에서 발견 시 해당 릴리스 실패. |
| 자연스러움 | 독자와 문체를 아는 사람의 5점 평가 | 30편×2명, 중앙값 4 이상·모든 원고 3 이상을 초기 검증 가설로 둔다. |
| 재작성 부담 | 원고를 쓸 수 있게 고치는 데 걸린 실제 시간 | 중앙값 5분 이내를 개선 목표로 측정한다. 이미지 업로드 시간은 별도다. |
| 자동화 | 승인된 기획에서 예외 없는 제작 경로의 완료율 | 공급자 가용·예산·입력 적격 여부를 나눈 분모를 보존한다. |
| 운영 | 재시작 후 중복 원고·중복 과금 예약 | 오류 주입 인수시험에서 0건. 실제 공급자의 중복 청구는 별도 대사한다. |

수치는 품질 목표이며 과거 실적이 아니다. 실제 30편과 인간 평가자는 개발 후 확보한다. AI 가상독자 60명을 인간 평가로 세지 않는다.

## 제품 요구사항 묶음
A. 블로그별 프로필과 관점: 주제·독자·편집 기준을 분리하고 프로필 변경을 버전으로 남긴다.
B. 수요와 기획: 실제 소스의 시점·한계를 보존하고 새로운 질문이 없는 소재는 탈락시킨다.
C. 집필: 근거 있는 답을 먼저 만들고 문체를 나중에 입히며 의미가 바뀌지 않았는지 확인한다.
D. 자산·출고: 실제 파일이 있으며 손쉬운 전송이 가능하다. 공개용과 검수용 파일은 분리한다.
E. 반복 운영: 일정·예산·체크포인트·예외함·원문 변경을 처리한다.
F. 학습: 실제 PV·수정 이력·정정·제작비를 사용하며 누락을 성공이나 0으로 만들지 않는다.

## 출시 범위
P0는 두 프로필 격리, 하나 이상의 실제 허용 소스, Naver 검색·Datalab 어댑터, 일반 웹 원문 어댑터, JSON 구조 집필, 재검수, 에셋 파일 업로드/권리, 전송 패키지, 수동 게시 기록, 보고서 가져오기다. YouTube 메타데이터·자막 및 SNS 공급자는 선택형 입력 어댑터로 계약과 입력 포맷을 우선 구현한다. 연결하지 못한 소스 때문에 전체 연구를 멈추지 않되 ‘최신 SNS까지 실시간 조사’했다고 표시하지 않는다.

## 제품의 경쟁력
단순 글 생성기가 아니라 ①정보 빈칸을 찾아내는 기획, ②원문과 실제 경험을 구분하는 기억, ③블로그별 일관된 관점, ④제목의 약속과 본문의 답 검사, ⑤게시 전 사람의 대기시간까지 포함한 신선도 관리, ⑥사용자 수정을 반영하는 편집 기억에 있다. 이 여섯 기능이 작동하지 않으면 대시보드가 있어도 출시 완료가 아니다.
