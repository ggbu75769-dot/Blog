# 03. 멀티블로그·주제 운영 명세

문서 기준: 2026-09-15 · 설계 동결: 4.1.0-r1 · 공개 게시: 사용자 수행


## 편집 브랜드 구조
큰 분야 1개와 자연스러운 인접 주제 3~4개를 초기 운영 가설로 제안한다. 숫자는 공식 노출 요건이 아니다. 프로필의 중심은 “누가 어떤 상황에서 어떤 답을 기대하는가”다. 주제 이름만으로 분류하지 않고 reader_job·editorial_lens·allowed_formats를 사용한다. 공식 검색 가이드는 주제 일관성을 권하지만 홈판 단일 주제 강제 규칙으로 해석하지 않는다.[S02]

## 프로필 필드의 의미
name은 편집 브랜드이며 가짜 실존인물이 아니다. core_topics/adjacent_topics/excluded_topics는 배열이다. reader_job은 독자의 실제 문제, editorial_lens는 자료를 비교할 기준이다. author_facts와 experience_records는 승인된 사실만 포함한다. style_examples는 사용권 있는 원고의 필요한 구간만 보존한다. profile_version 변경은 향후 작업에 기본 적용되며 기존 원고를 자동 재작성하지 않는다.

## 채널 선택의 초기 절차
신규 계정은 승인한 2~3개 후보 분야를 같은 관측 기간·허용 소스로 비교한다. 관심 근거, 반복 공급 가능성, 원문 접근성, 이미지 확보, 고유한 관점, 민감도, 편집비를 비교한 추천안을 한 번 승인받는다. 초기 추천 분야를 최신 인기 순위로 단정하지 않는다. 기존 계정은 사용자가 제공한 최근 글·통계의 범위에서 강점과 편집 부담을 확인하고 삭제·전면 주제 변경은 제안만 한다.

## 자동 라우팅 절차
1. 사건에서 중심 질문과 잠정 답을 만들고 entity를 정규화한다.
2. 각 활성 블로그의 core/adjacent/excluded 적합성과 최근 30개 기획을 비교한다.
3. 해당 자료·경험·이미지의 blog scope가 허용되는지 확인한다.
4. 동일 질문·동일 답이 다른 블로그에 예약되어 있으면 중복 후보로 분류한다.
5. 조건을 통과한 블로그 중 적합성·독창성·자료준비·대기열을 비교해 배정한다.
6. 트랜잭션에서 reservation_key를 확보한다. 경쟁 요청은 이미 있는 기획으로 연결한다.

reservation_key는 tenant + event + normalized_question_fingerprint + answer_fingerprint다. 정확 일치는 DB로 차단하고 의미상 중복은 별도 모델/임베딩 검토를 한다. 질문 문구만 바뀐 clone은 fingerprint가 다르더라도 잡아야 한다. 반대로 같은 핵심 사실을 언급한다고 모든 후속 글을 중복으로 삭제하지 않는다.

## 자원 배분
기본 활성 프로필 2개, 프로필당 READY 대기열 2편, 전체 대기열 6편을 시작 설정으로 제안한다. 사용자가 글을 올리지 않아 적체되면 신규 집필보다 대기 원고의 시의성과 정정을 우선한다. 10개 프로필 기능시험은 격리·스케줄·예산용이며 10개 계정을 반드시 만들라는 지시가 아니다. 새 채널 개설은 자동으로 하지 않는다.

주력 채널 목표를 먼저 보존하되 단일 급등 한 번만으로 다른 채널 예산을 전부 빼앗지 않는다. 탐색 예산은 전체 허용 예산 내 별도 한도로 둔다. 예산이 미설정이면 유료 작업은 비활성이다.

## 금지되는 공유
다른 블로그의 개인 경험을 자기 경험으로 재사용, 경쟁자 문체의 문장 단위 복제, 다른 인물로 가장하는 작성자 약력, 동일 글의 제목만 바꿔 분산, 조직적인 상호 링크와 가짜 반응을 금지한다. 여러 블로그 자체가 금지라는 뜻이 아니라 독자와 질문의 차별화를 제품 조건으로 두는 것이다.[S03][S10]

## 예시 프로필
디지털 생활: 바뀐 기능의 적용 대상·버전·예외를 먼저 설명한다. 공개 문서 비교형 중심.
생활 선택 기준: 보기 좋은 사진보다 실제 조건·동선·비용을 따진다. 체험 자료 없으면 사용기 형식을 쓰지 않는다.
방송·OTT 읽기: 실제 확인한 장면과 해석을 구분한다. 사생활 소문과 확인되지 않은 인물 의혹은 자동 생산 대상에서 제외한다.
이는 후보 편집 방향이며 사용자 실제 계정·경험·흥행 실적이 아니다.
