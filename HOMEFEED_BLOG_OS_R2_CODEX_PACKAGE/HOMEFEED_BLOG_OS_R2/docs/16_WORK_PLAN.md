# 16. 개발 작업계획서·마일스톤

문서 기준: 2026-09-15 · 설계 동결: 4.1.0-r1 · 공개 게시: 사용자 수행


## 실행 원칙
이 문서의 단계는 일정 약속이 아니라 완료 게이트다. Codex는 기존 저장소를 먼저 확인하고 새 서비스인지 기존 서비스 확장인지 구분한다. 이미 있는 인증·저장소·스택을 이유 없이 다시 만들지 않는다. 해당 세션에서는 가능한 작업까지 구현·시험·증거를 남기고 장래 백그라운드 수행을 약속하지 않는다.

## 개발 병렬화
M0의 계약 동결 이후 UI, adapter, renderer는 병렬 가능하다. schema·states·error code·revision hash는 한 명의 계약 담당자가 소유한다. 같은 파일을 서로 다른 agent가 동시 수정하지 않는다. 각 작업은 별도 branch/worktree를 사용하고 통합 담당자가 계약시험 후 합친다. 여러 역할로 같은 모델을 호출했다고 독립 인간 검토로 기록하지 않는다.

## PR 크기와 완료 보고
한 PR은 연결된 작업1~3개를 목표로 한다. 작업 ID, 변경파일, 테스트 명령·결과, 남은 연동·사람 입력, 위험·rollback을 남긴다. 실제 동작 없는 placeholder 화면이나 API의 무조건200 응답은 완료가 아니다. mock adapter는 mode=REPLAY이며 LIVE UI에 노출되지 않는다.

## Vertical Slice
가장 먼저 source fixture→적격 기획→blog 배정→근거팩→본문→검수→실제 export 파일이 이어지는 경로를 만든다. 이후 실제 허용 소스와 LLM 호출을 연결한다. 한 단계씩 mock을 제거한다. 처음부터 모든 SNS 공급자와 모든 템플릿을 만드는 것보다 주력 경로의 사실·문체·출력 품질을 우선한다.

## 운영 입력 부족 시
키·블로그·기존 글·예산이 없으면 M0~M5의 REPLAY 구현과 테스트는 계속한다. 실제 호출은 BLOCKED_EXTERNAL_INPUT으로 기록한다. 사용자에게 매 글 자료를 요구하는 수동기획 도구로 설계를 축소하지 않는다. LIVE 시험에 필요한 입력만 한 목록으로 남기고 개발 가능한 나머지를 끝낸다.

## 코드 변경 안전
git status·branch·untracked를 확인하고 사용자의 기존 변경을 보존한다. reset --hard·force push·운영 DB migration·secret rotation·배포를 자동 실행하지 않는다. 전체 설계가 필요하다는 이유로 기존 작동 기능을 임의 삭제하지 않는다. 상세 작업별 완료 조건은17번 문서와 contracts/tasks.json을 따른다.


## R1 작업 삽입
T051~T060이 추가되었다. 번호순이 아니라 contracts/task_order.txt를 사용한다. T004 전 T051/T052, 실제 자료 연결 전 T053/T054, 집필 품질 평가 전 T056/T057, 공개패키지 전달 전 T058을 통과한다. T060은 새 회귀검사의 실제 결과와 미실행 영역을 수집한다. reference_core가 제공되어도 앱 통합 작업 완료를 의미하지 않는다.


## R2 보완 우선 적용
내용·문체·독자 평가·독자용 출력의 상세는 docs/31~38을 함께 적용한다. 특히 부족한 내용은 문체로 덮지 않고 조사/재기획하며, 최종 본문의 실제 payoff 구절과 review 버전을 연결한다. R1 사실·권리·scope·최신성 gate는 약화하지 않는다. R2 예제는 인간평가·실제 에디터·트렌드 효과가 확인되지 않은 편집 기준용 원고다.
