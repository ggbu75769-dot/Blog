# 22. Codex 실행·개발 지시 가이드

문서 기준: 2026-09-15 · 설계 동결: 4.1.0-r1 · 공개 게시: 사용자 수행


## 읽는 순서
README→AGENTS→00 범위→01 PRD→10 architecture→16 plan→선택한 T 작업→관련 schema/API/AT 순으로 읽는다. 모든 문서를 한 프롬프트에 붙여 컨텍스트를 소모하지 않는다. Codex는 프로젝트의 AGENTS.md 계층을 읽으므로 루트에는 핵심 규칙과 문서 경로만 둔다. 기존 AGENTS와 더 상위 지시를 덮어쓰지 않는다.[S11]

## 저장소에 넣는 방법
신규 저장소: 패키지 파일을 프로젝트 루트에 두고 M0부터 시작한다.
기존 저장소: docs/specs/HOMEFEED_FINAL/ 같은 충돌 없는 경로에 넣는다. 패키지 AGENTS 내용을 기존 루트 파일과 검토해 병합하고, 자동 덮어쓰지 않는다. 기존 앱 경로와 문서의 제안 경로를 매핑해 기록한다.

## 작업 지시의 목표
‘계획만 작성’에서 끝내지 않는다. 해당 세션에서 선택한 T작업을 실제 구현→단위/계약시험→필요 통합시험→보고까지 진행한다. 사용자가 이미 맡겠다고 한 공개 게시를 자동화하는 데 시간을 쓰지 않는다. 키가 없어도 mock UI를 완제품으로 속이지 말고 REPLAY와 LIVE 의존을 나눈다.

## 작업별 보고 형식
작업ID / 입력 확인 / 수정파일 / 구현 내용 / 실행명령 / 실제 결과 / 미실행 이유 / 남은 운영입력 / 다음 의존 작업 / rollback. 사람이 보지 않은 화면·실행하지 않은 테스트·읽지 않은 원문을 확인했다고 적지 않는다.

## 테스트 지시
패키지 tools/validate_bundle.py는 설계 계약의 정합성 검사다. 제품 기능시험이 아니다. Codex는 각 AT의 실제 test file과 실행결과를 새로 구현해야 한다. test stub skip을 pass로 집계하지 않는다. 본문 품질은 실제 인간 블라인드 평가 전까지 미검증이다.

## 종료 조건
선택한 작업과 의존계약을 구현·검증하면 마무리한다. 무한 재귀개선·무한 에이전트 호출은 금지한다. 개선이 필요하면 근거와 다음 T작업으로 남긴다. 신규 paid API, 데이터 삭제, 외부 게시, 운영배포, 대규모 migration은 사용자가 별도로 승인한 범위 밖에서 실행하지 않는다.


## R1 코드 연결
기존 final.1을 이미 구현 중이면 db/R1_MIGRATION_PLAN.md와 docs/29에서 영향을 확인한다. 현재 소스/기존 migration을 파악하지 않고 새 DDL을 운영 DB에 붙여넣지 않는다. 원본 변경을 보존한 별도 branch/worktree에서 적용한다. 여러 검토 관점을 나눌 수 있지만 별도 에이전트를 실제 사용하지 않았다면 여러 에이전트 검증을 수행했다고 쓰지 않는다.
