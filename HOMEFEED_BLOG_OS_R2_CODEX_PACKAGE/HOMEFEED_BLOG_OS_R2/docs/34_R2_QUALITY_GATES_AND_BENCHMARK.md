# 34. 원고 품질 평가와 개선 실험

## 판정기는 하나의 총점이 아니다
Q0 사실·권리·실제 경험·최신성, Q1 내용의 답과 가치, Q2 제목과 독자 기대, Q3 흐름과 문체, Q4 실제 출력, Q5 실제 관심·성과를 나눈다. 높은 Q3가 틀린 사실을 상쇄하지 못한다. Q4 코드 검사를 통과했다고 Q1~Q3가 입증되는 것도 아니다.

## 편집 차원과 앵커
| 차원 | 확인할 근거 | 실패 예 |
|---|---|---|
| payoff | 독자의 이해·판단을 바꾸는 정확한 최종 구절 | ‘도움이 됩니다’만 반복 |
| promise | 제목의 기대와 이를 충족하는 본문 | 세 가지라지만 둘뿐이거나 다른 이야기 |
| coherence | 문단 사이의 질문과 답 연결 | 서로 무관한 지식 나열 |
| voice | 승인된 관점과 실제 문장, 불필요한 반복 여부 | 모든 글의 동일한 도입·추천·맺음 |
| specificity | 근거가 있는 조건·비교·구체적인 예 | 가짜 체험이나 숫자로 구체성을 꾸밈 |

PASS / FAIL / UNKNOWN으로 분리한다. ‘AI 작성 확률’은 만들지 않는다. 이유에는 최종 block과 문구가 들어가야 한다. 판단할 자료가 없으면 UNKNOWN이다. 중대한 실패가 하나라도 있으면 평균점수로 통과시키지 않는다.

## 독립 검토의 뜻
작성 모델에게 검수 프롬프트를 한 번 더 보냈다는 이유로 독립적인 인간 평가라고 부르지 않는다. 별도 호출도 같은 근거 오류·모델 편향을 공유할 수 있다. 원문 검토와 실제 독자 평가를 구분한다. 프로덕션에서는 검토자의 신원과 정책을 서버에서 인증하며 writer가 review ID를 바꿔 스스로 승인할 수 없다.

## 실제 독자 평가를 두 단계로 실시
A: 제목·대표이미지·첫 화면만 보여주고 예상 내용과 읽고 싶은 이유를 기록한다.
B: 본문을 읽고 기대가 충족됐는지, 새로 이해한 내용, 지루했던 구간, 실제 게시를 위해 수정할 부분을 기록한다.

A의 클릭 의향이 높지만 B에서 약속이 어긋나면 실패다. 사실·권리 검토는 별도 원문 화면에서 한다. 제목에 속는 정도를 개선 지표로 삼지 않는다.

## 비교 실험의 공정성
- 동일한 실제 사건 묶음, 동일 브리프·원문·허용 자산·문체에서 집필 경로만 비교한다.
- 단일 호출 기준선도 최선을 다하도록 하고 가짜 체험·허위 내용을 허용하지 않는다.
- 생성 실패, 보류, 미완성 원고를 분모에서 빼지 않는다.
- 새 경로가 더 많은 원문과 비용을 썼다면 동일 자원 비교와 실제 품질 비교를 별도 보고한다.
- 같은 사건의 여러 변형을 독립 표본처럼 세지 않는다. 사건 단위로 학습·검증·최종 평가를 분리한다.
- 후보 A/B 순서를 무작위·교차 배치하되 최종 레퍼런스 글을 이미 본 평가자의 학습 효과를 기록한다.
- 유지시간은 긴 글·혼란·중단으로도 늘 수 있으므로 단독으로 만족도라고 읽지 않는다.

## 초기 실험 범위와 수용 기준
두 블로그 이상, 최소 세 형식, 서로 다른 사건 묶음으로 30개 사례를 수집하는 R1 계획을 유지한다. 실제 두 평가자가 독립 기록하고, 분쟁은 원점수와 합의 결과를 모두 보존한다. 자연스러움은 5점 척도 중앙값 4 이상, 개별 3 미만 재검토, 중대 사실 오류/가짜 체험/핵심 미완성 0을 초기 운영 목표로 둔다. 이 값은 검증 전 제품 기준안이다.

수정시간은 기사 길이·주제 난도·사실 확인과 단순 문체 수정을 분리한다. 평균만 보고하지 말고 중앙값·상위 꼬리·수정 불가를 보존한다. 5분 이내라는 목표가 출처 확인을 건너뛰라는 뜻이 아니다.

## 이번 샘플의 한계
R2의 3개 원고는 이 세션에서 직접 집필한 편집 예제다. R1 원고 한 편은 실제 첨부 원문을 비교한다. 나머지 두 편은 동일 조건의 이전 자동작성 대조군이 없다. 세 편 모두 사용자·독립 독자 평가 NOT_RUN, 실제 자동 파이프라인 NOT_RUN, 에디터 입력 NOT_RUN, 바이럴 성과 NOT_MEASURED다. 샘플에 임의의 90점·승률·인간 판별 통과 점수를 붙이지 않는다.

## 코드와 사람의 경계
`editorial_r2/reader.py`는 최종 문구 앵커, 버전, 참조, 내부 메모, 정확한 중복과 출처 표시를 검사한다. 진실성·독창성·자연스러움을 자동 증명하지 않는다. 검토 결과가 없으면 EDITORIAL_REVIEW, 실제 독자 보정이 없으면 OWNER_REVIEW로 돌린다. 사용자 공개 게시는 계속 수동이다. 초기 보정 후 낮은 위험 범위의 자동 편집 승인 정책은 서버가 버전 관리하고 회귀하면 철회한다.
