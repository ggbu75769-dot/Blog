# 35. 독자용 출력과 샘플 개정 기록

## 출력물은 두 종류
공개 원고에는 제목·본문·필요한 표·캡션·정상적인 출처만 넣는다. 내부 기획 점수, claim ID, 모델 분석, 검수 결과, 대체 제목은 비공개 sidecar로 분리한다. 모델이 claim을 붙이지 않았더라도 최종 사실 검토는 전체 본문을 확인한다.

출처를 보기 좋게 만든다는 이유로 출처를 없애지 않는다. R2 미리보기는 해당 사실 문단 끝에 작은 독자용 각주 번호를 붙이고 마지막에 기관명과 원문 링크를 남긴다. 내부 PUB/CLAIM ID와 독자용 각주 번호는 분리한다. 본문 문맥에 기관명을 자연스럽게 넣는 방식도 편집 가능하나 중대한 주장과 출처의 관계를 숨기지 않는다. TXT에도 대응하는 각주와 기관명·원문 URL 목록을 제공한다.

## 실제 코드 경로
`reference_core/render.py`: R1 진단·이스케이프 시험 경로로 보존.
`editorial_r2/reader.py`: 독자형 HTML/TXT 참조 렌더러. 최종 제품에서 교체 연결할 대상.
`tests/adversarial`: 악성 문자열 등 부정 예제 전용. public samples와 별도.
`examples/editorial_r2`: 최종 독자형 텍스트 예제와 비공개 상태·편집 주석.

이 함수로 HTML을 만들었다고 네이버 SmartEditor와 완전히 호환되는 것은 아니다. 실제 붙여넣기 검증은 NOT_RUN이다. 이미지를 계획만 하고 완료 처리할 수 없다. 샘플은 의도적으로 텍스트 설명 품질을 보여주며 홈피드 카드 자산까지 갖춘 전체 게시 패키지가 아니다.

## 예제 1: R1 Datalab 원고 수정
원본: `00_R1_ORIGINAL.txt`.
R1 제목: 검색 추세의 100, 검색한 사람이 100명이라는 뜻은 아닙니다.
R2 제목: 검색 추세가 둘 다 100인데, 어느 쪽이 더 인기일까?

원본에서 같은 뜻을 반복하던 도입·결론을 줄였다. 이론 설명 대신 실제 독자 판단 문제인 ‘서로 따로 조회한 두 그래프의 최고점 비교’를 중심으로 잡았다. 10→20과 1,000→2,000을 각각 정규화하면 같은 50→100이 되는 가상 예를 넣었다. 실제 검색량이나 API 결과라는 오해가 없도록 표 바로 앞에 가정임을 명시했다. 각 묶음이 따로 자기 최댓값을 기준으로 변환되는 설명 예이며 네이버 내부 비공개 계산식의 구현이라고 주장하지 않는다.

같은 조건으로 요청해야 한다는 안내와 절대 검색량은 아니라는 한계, 일·주·월 시간 해상도를 남겼다. 가상 계산 추가 자체는 ‘새로운 발견’이 아니라 공식 개념을 이해시키는 편집 기여다.

## 예제 2: Google 포토
제목: 구글 포토에 보이는 사진, 휴대폰에서 지워도 될까?
핵심: 앱에 보이는 것과 백업 완료는 다르며, 기기 사본을 정리한 뒤 접근 방식도 달라진다.
두 공식 도움말을 하나의 결정 문제로 연결했다. 실제로 삭제하거나 테스트했다고 쓰지 않았다. 즉시 대량 삭제를 지시하지 않고, 계정·대상 사진 백업·제거 대상을 확인할 때까지 멈추게 했다. 삭제 도움말의 일부 발췌는 확인했지만 재열기에 실패했으므로 휴지통 삭제의 세부 동작을 본문 핵심 주장으로 쓰지 않았다.

## 예제 3: USB-C
제목: 충전은 되는데 모니터는 안 뜨는 USB-C, 케이블 문제일까?
핵심: 충전 성공과 DisplayPort 대체 모드의 영상 지원은 같은 확인이 아니다.
연결 점검 순서를 포트→연결 장치·케이블로 좁혔다. 모든 USB 그래픽 방식에 일반화하지 않았다. 실제 장비 고장이나 특정 모델의 기능을 판정한 글이 아니다. Microsoft와 VESA·USB-IF의 적용 범위를 보존했다.

## 변경으로 입증한 것 / 입증하지 못한 것
입증: 실제로 다른 원고를 작성했고, 원문 링크·표·문단이 출력 파일에 보존되며 내부 코드가 독자 표시로 전환됨.
편집 판단: 원본보다 질문과 비교 예가 명확해졌다고 이 세션에서 판단함.
미입증: 실제 독자가 더 선호하는지, 자동 파이프라인이 반복 생성할 수 있는지, 해당 주제가 현재 홈피드에서 유망한지, 실제 클릭·조회·공유 성과.

## 다운로드 시점
R1의 사실·권리·원고 버전·실제 파일 확인에 R2 최종 편집 review의 해시를 연결한다. 새 원고에 이전 review를 붙일 수 없다. 샘플·REPLAY 경로는 LIVE로 자동 승격하지 않는다. `sample_status.json`은 공개 본문 밖에 두되 데모 화면과 제공 설명에서 그 한계를 숨기지 않는다.
