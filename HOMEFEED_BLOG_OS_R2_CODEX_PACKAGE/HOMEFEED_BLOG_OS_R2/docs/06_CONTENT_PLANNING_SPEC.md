# 06. 주제→내용 기획 작업명세

문서 기준: 2026-09-15 · 설계 동결: 4.1.0-r1 · 공개 게시: 사용자 수행


## 좋은 기획의 계약
ContentBrief는 독자 한 명의 한 중심 질문, 한 문장 핵심 답, 지금 읽을 이유, 기존 글이 이미 답한 것, 우리 글이 추가할 것, 근거, 제목의 약속, 첫 문단의 답, 섹션별 역할, 시각 자료 계획, 위험과 중단 조건을 가진다. ‘키워드 몇 회 포함’은 성공 계약이 아니다.

## 기획 생성 절차
1. 사건·검색 의도·홈피드 관측을 분리해 읽는다.
2. 같은 독자가 지금 가질 수 있는 질문 3~5개를 만든다.
3. 각 질문에 대한 기존 결과를 비교하여 답이 이미 충분한 질문을 제거한다.
4. 해당 블로그 관점과 확보 가능한 근거로 새 답을 제시할 수 있는 기획을 선별한다.
5. 중심 주장과 뒷받침할 자료를 함께 계획한다.
6. 필요한 이미지가 없을 때 가능한 대안을 계획하되 본문 약속을 유지할 수 있는지 확인한다.
7. 제목·대표이미지·첫 화면 후보를 묶어 읽을 이유를 평가한다.
8. 논지를 공격하는 counterbrief를 작성해 과장·범위 오류·무의미한 차별화를 찾는다.
9. 통과한 브리프만 작성 큐에 넣는다.

## 기획 품질의 실패 예시
실패: ‘드라마 A가 인기니까 등장인물 정리’만 있고 새 질문이 없다.
보완: 실제 확인한 장면의 맥락을 해석하고 다른 해석과 근거를 구분한다.
실패: ‘신제품이 나왔으니 장점10개’만 제시한다.
보완: 기존 이용자가 바꿔야 할 조건과 아직 적용되지 않는 범위를 공식자료로 비교한다.
위 예시는 현재 인기 소재라는 사실 주장이 아니라 기획 방식 설명이다.

## 형식 선택 규칙
| article_type | 적합한 질문 | 필수 내용 | 금지하는 생략 |
|---|---|---|---|
| change_explainer | 무엇이 바뀌고 누구에게 해당하는가 | 전후·시점·대상·예외 | 이전 조건을 지어내기 |
| comparison | 우리 조건에는 무엇이 맞는가 | 같은 기준·차이·선택 조건 | 다른 모델·시점을 같은 비교로 표시 |
| interpretation | 이 장면·발언을 어떻게 이해할까 | 실제 확인 범위·근거·해석 | 보지 않은 영상의 장면 묘사 |
| how_to | 어떻게 실행하는가 | 대상버전·단계·실패 상황 | 검증하지 않은 단계의 성공 보장 |
| experience | 실제로 해보니 어땠는가 | 경험 record·기간·관찰 | 근거 없는 1인칭 체험 |
| decision_guide | 어떤 기준으로 판단할까 | 기준·조건·제한 | 무조건 좋은 선택이라는 결론 |

## 구성 계획
섹션마다 reader_value를 적고 핵심 질문과 관계없는 문단은 제거한다. 기본적으로 첫 화면에서 중심 답이나 방향을 제시하고, 뒤에서 근거·차이·예외를 풀어간다. 모든 글을 같은 서론/장점3/단점3/결론 구조로 만들지 않는다. 글자수와 사진수는 내용에 필요한 만큼 계획하되 가독성을 점검한다. 범용 문자수 목표가 홈판 노출 조건이라는 규칙을 만들지 않는다.

## 카드 패키지 기획
초기 제목 후보8·이미지 방향3·도입 방향2를 만들되 최종 후보3개 이하로 줄인다. 제목의 숫자·반전·대상은 실제 본문과 연결한다. 대표이미지의 미해결 궁금증은 본문에서 해소할 수 있어야 한다. 클릭 의향뿐 아니라 내용을 오해하지 않는지도 평가한다. 합성 인물·현장 사진으로 사실을 꾸미지 않는다.

## 편집점수와 실험
LLM 점수는 진단용이다. 질문 명확성·새 기여·근거·블로그 적합성·카드 일치·실행가능성을 항목별로 이유와 함께 출력한다. 모델 점수만으로 출고하지 않는다. 실제 블라인드 비교에서는 A/B 어느 버전인지 숨기고 기대한 답과 실제 답의 일치를 질문한다. 인간 평가 미실행 상태를 유지한다.

## 시간과 폐기
planned_release_window는 사용자의 게시 가능한 시간대를 참고한 내부 준비 목표다. opportunity_review_at은 재검토 시점이지 관심이 그때 정확히 끝난다는 예측이 아니다. 공개 일정이 취소되거나 최신 사실이 바뀌거나 같은 답이 이미 충분해지면 REFRAME/DEFER/REJECT 중 하나로 바꾼다. 작성비를 이미 썼다는 이유로 부적합한 글을 출고하지 않는다.


## R1: 편집 경쟁과 정보 가치
같은 사건·같은 블로그에서 기획3개를 비교한다. 후보마다 독자의 현재 질문, 기존 답, 새 기여를 실제 근거와 연결하고 반대 설명을 기록한다. 숫자로만 순위를 매기지 않고 왜 선택했는지와 탈락 이유를 보존한다. 소수의 우수한 글만 평가 자료로 남기지 않는다. 선택모듈과 집필모듈의 개선을 분리 평가한다. 다른 소재의 좋은 글과 비교해 집필모델 개선이라고 주장하지 않는다.


## R2 보완 우선 적용
내용·문체·독자 평가·독자용 출력의 상세는 docs/31~38을 함께 적용한다. 특히 부족한 내용은 문체로 덮지 않고 조사/재기획하며, 최종 본문의 실제 payoff 구절과 review 버전을 연결한다. R1 사실·권리·scope·최신성 gate는 약화하지 않는다. R2 예제는 인간평가·실제 에디터·트렌드 효과가 확인되지 않은 편집 기준용 원고다.
