# 14. 월 100만 조회 목표·통계·실험 계획

문서 기준: 2026-09-15 · 설계 동결: 4.1.0-r1 · 공개 게시: 사용자 수행


## 목표 유지
주력 네이버 블로그 하나의 달력 월1,000,000PV가 목표다. 포트폴리오 합계·티스토리·자체 블로그 합계를 별도 계기판으로 둔다. 달력 월은 Asia/Seoul 월초00:00부터 다음월초00:00 미만이다. 30일 평균은1,000,000/30≈33,333PV지만 실제 월 일수로 목표 페이스를 계산한다. 누적 조회수를 월 조회수와 혼동하지 않는다.

## 산술 시나리오 — 실적 예측 아님
기존 글이 당월100,000PV를 만든다고 가정할 때 신규60편은 평균15,000PV,90편은10,000PV,120편은7,500PV가 필요하다. 월말 발행한 글의 다음달 PV를 이번 달에 합산하지 않는다.120편이 여러 블로그에 나뉘면 주력120편으로 계산하지 않는다.

신규120편에서 대형10편×50,000+중형30편×10,000+일반80편×1,500+이전글80,000=1,000,000은 별도의 가정 예다. 이때 대형비율은10/120≈8.33%다. 그 비율을 현재 성공확률로 사용하지 않는다. 서비스는 기획 선택과 완성도를 높여 이런 분포를 실제로 개선할 수 있는지 관측한다.

## 정확한 지표
PV, visits, unique_visitors, homefeed_referrals, referral_ratio, content_impressions, content_clicks, ad_impressions, ad_clicks는 서로 다르다. 실제 콘텐츠 노출과 클릭이 같은 entity·surface·기간·필터일 때만 CTR를 계산한다. 유입 비중의 분모는 유입 수이므로 ratio×PV를 홈판 조회수로 만들지 않는다.[S07][S08]

status는 OBSERVED/PARTIAL/NOT_UPDATED/NOT_AVAILABLE/USER_ENTERED를 구분한다. 0은 원본이 실제0을 보고한 경우에만 숫자0이다. 블로그 전체 통계를 개별 원고로 나누어 실제 글별 지표처럼 만들지 않는다. 보고서에 없는 경쟁자 지표는 생성하지 않는다.

## 수동 게시에 따른 귀속
원고 exported_at이 아니라 user posted_at을 성과창의 기준으로 사용한다. 사용자가 기록하지 않으면 미게시로 단정하지 않고 PUBLICATION_UNKNOWN이다. 통계 URL과 원고가 매핑되면 연결 제안을 한다. 동의 없이 다른 글의 통계를 연결하지 않는다. 실제 게시본이 바뀌었으면 원고 버전 차이를 표시해 학습 오염을 줄인다.

## 보고서 가져오기
원본파일 hash→필드 매핑 preview→기간·계정·단위 검증→중복·revision 확인→commit→집계→오류 목록. 알려지지 않은 열은 버리지 말고 raw payload에 보존한다. 다른 timezone과 누적/일별 데이터를 섞으면 매핑 검토를 요구한다. 업로드 자료에 포함된 개인정보·댓글 작성자는 최소화한다.

## 성과창과 비교
24h/72h/7d/28d를 분리하고 mature 여부를 보존한다. 아직 관측창을 채우지 못한 원고를 실패로 세지 않는다. 같은 사건의 여러 글은 독립 표본이 아니므로 사건별 그룹을 나눈다. 게시 시간·계정·소재가 다른 자연관찰을 무작위 실험처럼 표현하지 않는다. 저조회수를 곧바로 제목 탓으로 단정하지 않는다.

## 학습 루프
수요→기획→최종 카드→본문 구조→실제 게시시간→원본 성과→사용자 수정·정정의 연결을 남긴다. 단일 대박 이후 모든 글을 같은 형식으로 바꾸지 않는다. prompt/profile/ranking version을 보존하고 시간순 holdout으로 평가한다. 외부 경쟁자 점수와 자체 실적을 구분한다. 데이터가 부족하면 수치 예측 모델을 만들지 않고 설명 가능한 규칙을 유지한다.

## 실험 카탈로그
E01 제목 기대와 실제 답 일치 / E02 대표이미지의 대상 이해 / E03 첫 화면 답 우선 / E04 비교표의 새 가치 / E05 문체 편집 전후 / E06 원문 인용 배치 / E07 적절한 설명 깊이 / E08 핵심→인접 분야 확대 / E09 반응확인형 / E10 일정선점형 / E11 새 질문 후속연재 / E12 기획 정렬규칙 변경.
각 실험은 가설·primary metric·guardrail·관측창·사전 최소정보량·예산·변경요소를 가진다. 자연스러움과 내용 검증은 블라인드 편집시험, 성과는 관찰/준실험으로 구분한다. 필수 사실·권리 게이트는 실험하지 않는다.

## 운영 확대 기준
P0 목표는 실제 소스부터 HANDOFF_READY까지다. 이후 원고의 오류·재작성 시간·효과가 검증된 프로필에 생산 여력을 추가한다. 일일 발행량은 사용자의 수동 처리량·자료 준비·예산에 맞춘다. 초반 일1~2편은 시험 출발점이며 네이버 안전 규칙이 아니다. 일정상90일은 실험 운영 구간으로 제안할 수 있지만 월100만 달성 약속은 아니다.


## R1: 성공편향과 current 수치
선택·탈락·보류된 기획을 모두 보존한다. 미게시/기록불명은 조회수0 사례가 아니다. 비교는 실제 게시 시점 이후 성숙한 창을 사용하며 미래 통계를 기획 당시 입력으로 넣지 않는다. 같은 사건은 하나의 그룹으로 나눠 holdout 유출을 방지한다. 같은 논리키의 current metric은 DB unique 인덱스로 하나만 유지하며 수정 전 행 비활성화와 새 행 삽입은 같은 트랜잭션이다. 월누적·일별 중복과 숫자0/미갱신은 의미 검사로 차단한다.
