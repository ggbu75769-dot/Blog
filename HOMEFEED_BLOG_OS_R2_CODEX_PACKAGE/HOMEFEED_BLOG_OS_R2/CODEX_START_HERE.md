# Codex — R2 원고 품질 개정 적용

사용자의 목표는 주제부터 내용 기획·조사·집필·문체·검수·실제 출력까지 자동화하는 네이버/티스토리/자체 블로그 편집 시스템이다. 공개 게시는 사용자가 한다. 핵심은 원고 내용과 읽기 품질이다. 문서 수·에이전트 수·검사 숫자 늘리기로 대신하지 말 것.

## 첫 실행
1. git status, 기존 AGENTS.md·코드·문서를 읽고 사용자의 변경을 보존한다. 임의 운영 배포·DB변경·결제·로그인을 하지 않는다.
2. README, docs/31~38, 실제 세 샘플과 원본 비교를 먼저 읽는다.
3. 기존 docs/00·01·10·16과 contracts/task_order.txt를 확인한다. R2 작업은 contracts/r2/work.json의 의존순서를 연결한다.
4. 패키지 검사들을 실제 실행해 현재 기준선을 기록한다. 설명만 하고 종료하지 말고 가능한 참조 코드와 앱 경로를 구현한다.

## 구현 우선순위
우선 실제 글 한 편의 완성 경로를 연결하라. 좋은 기획 이유→독자에게 남는 답→실제 근거→최종 본문의 구절→해당 블로그 문체→정상 출처 표시가 보여야 한다. 같은 핵심 설명을 되풀이하는 문단은 고치되 안전 조건·예외·진짜 출처는 제거하지 않는다.

R1 예제를 그대로 복제해 모든 글에 같은 시작과 맺음을 쓰지 말라. 참고 샘플은 사람평가를 거친 절대 정답이 아니다. 사용자의 실제 문체와 독자 평가로 바뀔 수 있다. 없는 체험·독자 반응·영상 장면·숫자를 추가하지 말라.

## 코드 연결
- R1 schema/core/gate를 유지하며 R2 reader renderer와 editorial review sidecar를 추가한다.
- `editorial_r2/reader.py`는 구조/참조 검사다. 진실·자연스러움·바이럴을 자동 판정하는 완성 모델로 표시하지 않는다.
- 부족한 payoff는 추가 조사, 잘못된 질문은 재기획, 반복은 부분 편집. 기계적 재생성 루프를 만들지 않는다.
- 진짜 review identity와 정책은 인증된 서버에서 가져온다. writer JSON이 스스로 PASS를 만들 수 없다.
- 실제 LLM 연결이 없으면 REPLAY 경로를 개발한다. 직접 작성된 샘플을 API 자동집필 결과라고 기록하지 않는다.
- 수동 게시 전 다운로드 시점의 사실·권리·원고 해시·필수 자산 재검사를 우회하지 않는다.

## 반복 개선
결함 위치와 이유→실패를 재현하는 시험/독자 평가→최소 수정→최종 사실·의미 재검수→정상 사례와 반례 회귀→결과 기록 순으로 진행한다. 기준을 낮춰 PASS로 만들지 말라. 같은 결함이 반복되거나 비용을 초과하면 한계를 표시하고 다른 준비된 기획을 진행한다.

## 보고
완료한 작업과 변경 파일, 실제 시험 결과, 실제 생성된 원고, 사람이 고쳐야 하는 부분, 미실행 시험을 나눠 보고하라. 실제 두 독자의 평가·수정시간·네이버 에디터 확인·홈피드 지표가 없으면 미검증으로 남겨라. 최종적으로 독자가 읽을 글을 먼저 보여주고 시스템 설명은 뒤에 둬라.
